HOW I BUILD

Step by step, with a real example each time.

The three release notes from above, then the method I use when something breaks. The debugging example is the Amani Community Trust mobile menu, written up in full on the About page.

Release notes

01 Build with intentInterfaces should feel considered, move naturally and work on the devices people actually use.Example: Stride's checkout wizard and configurator, built with no framework. Stride
02 Test the real pathsA project is not finished when it looks right on one machine.Example: twelve role based verification scripts on the Cheliv Care Platform. Cheliv Care Platform
03 Ship with careDeployment is part of the product.Example: fourteen repeatable WP-CLI scripts that rebuild the Trackpoint site on a fresh install. Trackpoint

When something breaks

01 ObserveThe mobile menu on Amani Community Trust rendered in the wrong position. Not "broken," specifically wrong.
02 HypothesizeSomething in the header was changing how a child element's fixed positioning was calculated.
03 TestRemoved properties from the header one at a time rather than guessing at a full rewrite.
04 IsolateA backdrop filter on the header was quietly creating a new containing block for its fixed position children.
05 FixMoved the mobile menu to be a direct child of the body instead of the header.
06 VerifyConfirmed the menu behaved correctly across the breakpoints it had failed at before.
07 Ship, and remember itMonths later, the identical bug showed up on ShelemJ Resources. That time it took minutes, not hours, because the mechanism was already understood.

Read the whole debugging story on the About page
