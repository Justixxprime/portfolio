Cheliv Compassionate Care

A home healthcare provider needed a site that felt trustworthy and easy to navigate for people who might be stressed or in a hurry. Built during frontend training, 2025.

This page is the 2025 training site. A simple marketing site built during frontend training and kept live as a before picture. The healthcare software project is a different build: Cheliv Care Platform (development build, demonstration data).
chelivcompassionatecareplusinc.vercel.app

The brief

A home healthcare provider needed a marketing site that did one thing well: reassure a visitor who is already stressed, rather than add to that stress with a confusing layout or a wall of clinical text.

What it covers

Service pages and disease management program listings, written to explain what the provider does without overwhelming someone who is looking for help for a family member. A working request information form connects visitors directly to the care team, so the site does more than describe services, it starts the actual conversation.

Where this sits in the timeline

This was built while I was still in frontend training, alongside the E Commerce Showcase site, before I completed that program in January 2026. Everything else on this site was built after. The same attention to detail I picked up running lab assays shows up in how closely I checked this one before calling it done.

What I would change today: the intake form has no confirmation email back to the visitor, only a message to the care team. Someone reaching out while stressed deserves an immediate acknowledgment that their message actually sent.

WHY REACT, WHEN MOST OTHER PROJECTS HERE ARE PLAIN HTML
Requirement: a training exercise specifically meant to practice component based frontend development → Constraint: the site itself did not need React technically, a static site would have worked → Decision: React anyway, because the point was the practice, not the smallest possible build → Consequence: more setup than the project strictly needed, in exchange for real reps with component structure before using it on a project that actually required it

Not every technical decision on this site was made purely for the end product. This one was made for what I needed to learn at the time, and I would rather say that plainly than pretend it was a purely technical call.
