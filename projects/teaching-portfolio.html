Case study
Client system

Teaching Portfolio

Built for a specialist working one to one with children with autism, Down syndrome, and developmental delays. The point was never the front end, it was handing her control.

The client

Jennifer Amaka works one to one with children with autism, Down syndrome, and developmental delays. Her portfolio needed to do two very different jobs at once: present her work publicly, and keep sensitive case material genuinely private.

Editorial control, without code

A Decap CMS sits behind the site, so Jennifer can write and publish her own articles directly, without a pull request or a message to me every time she wants to add something. Cloudflare R2 stores her media with bandwidth conscious defaults, so hosting images and files does not become an ongoing cost problem.

Real access control, not hidden markup

The private portfolio section is password gated through Supabase authentication, and sits behind a Cloudflare Worker that enforces access on the server. That distinction matters: a section merely hidden by client side JavaScript can be reached by anyone who knows to look at the page source. A Worker sitting in front of it actually refuses the request server side if the visitor is not authenticated.

Why this is a different skill than the rest

Most of the other projects here are code I maintain directly. This one was built so someone with no coding background could run the content side of it herself, indefinitely, without needing me. That is a genuinely different kind of deliverable than a site that only I can update.
